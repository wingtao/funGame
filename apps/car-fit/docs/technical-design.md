# 买车前，先算算 · 技术方案

日期：2026-11-05；状态：首版已实现，运行与验证见 [项目 README](../README.md)。关联：[产品设计](product-design.md) · [视觉要求](design-style.md) · [纯前端技术基线](../../../docs/frontend-architecture.md)。PRD 是公式与评分规则的唯一业务依据。

## 1. 架构与依赖

使用 React + TypeScript + Vite、React Hook Form + Zod、Tailwind / Radix。新增 decimal.js 负责贷款、比例和费用中间值计算。首版使用 HTML / CSS 横向条形图，不引入完整图表库。所有依赖随站点打包，无运行时服务。

```text
src/
  app/                 App、视图 reducer、恢复入口
  domain/
    schemas.ts         草稿 / 有效输入 / 存储 schema
    questions.ts       六题、选项和权重
    money.ts           金额字符串解析与 Decimal 边界
    loan.ts            月供与逐期还款明细
    costs.ts           月支出、结余、持有总成本
    scoring.ts         两维分数、贡献与解释
    comparison.ts      A/B 对比及差额
  features/
    assessment/        开场、需求问答、预算表单
    results/           摘要、账单、规则说明
    comparison/        A/B 编辑与比较
    sharing/           分享白名单与卡片
  components/          表单基础控件、原创角色、图表
  platform/            storage、图片生成与文件分享
  styles/              语义变量与主题
```

测试与被测 domain 模块相邻或置于 tests；端到端流程放 e2e。

## 2. 数据模型与视图

| 模型            | 主要内容                                         | 约束                             |
| --------------- | ------------------------------------------------ | -------------------------------- |
| AssessmentDraft | 六题可空答案、原始字符串字段、当前步骤、示例标识 | 可不完整但必须结构合法           |
| ValidScenario   | 家庭收支、购车、贷款、用车、持有年限与残值       | schema 校验通过才可计算          |
| EnergyInput     | fuel 或 electric 的辨识联合                      | 只计算当前能源类型，不混用旧字段 |
| LoanSchedule    | 每期本金、利息、剩余本金                         | 由有效方案派生，不持久化         |
| ScenarioResult  | 现金流、持有总成本、分数、解释代码               | 纯函数派生，界面统一格式化       |
| ComparisonState | 相同需求答案、A/B 完整方案与独立编辑草稿         | 快照必须复制，不能共享可变对象   |
| CarShareModel   | 角色、需求分、通用结论、作品名称                 | 无经济分、账单或财务原值         |

视图使用辨识联合表示 welcome / questions(index) / household / vehicle / results / comparison。动作包含开始、回答、前后步、更新草稿、提交、创建对比、重置。打开不合法结果视图时返回首个缺失步骤，UI 不依赖不可信 hash 状态。

表单输入不直接改有效方案。修改对比时保留最后有效结果；有字段未完成或出错时标记“待修正，当前为上次有效结果”，不能把旧结果伪装成新结果。

## 3. 计算管线与精度

```text
字符串草稿 → schema / 金额解析 → ValidScenario
  → LoanResult + OperatingCosts
  → CashFlow + OwnershipCost
  → Scores + ExplainReasons
  → 格式化展示 / Comparison / ShareModel
```

- 金额文本按十进制字符串解析成整数分，禁止先经过二进制浮点 Number 再乘 100。Decimal 配置明确有效精度（建议 28 位）和四舍五入模式，不在组件中设置全局精度。
- 百公里能耗、里程和利率也先校验字符串再转换；有限、非负、上限等规则在 schema 层统一实现。
- 月供公式中 r=0 单独分支；全款方案不要求贷款字段。正利率使用 Decimal 幂运算，避免小利率相减损失精度。
- 逐期还款保持高精度中间值，最后一期结清残余本金；展示分的取整与内部利息累计分开，注明属于估算而非银行精确账单。
- 持有期利息只取实际持有期内贷款月份，剩余本金单列；月供本金、车价与折旧不重复相加。
- 评分仅使用未取整金额，最后才舍入整数分数并执行赤字封顶。解释使用稳定 reason code 与参数，不反向解析展示字符串。
- 纯函数显式接收 ruleVersion，首版固定 v1；旧草稿在规则升级后重新计算并说明版本变化。

## 4. 存储、隐私与分享

使用 `fungame:car-fit:v1`，Envelope 保存 schemaVersion、ruleVersion、updatedAt、草稿与 A/B 配置。根组件惰性初始化读取，写入策略和降级按公共技术基线。

分享只能调用 `createCarShareModel(result)`，函数返回白名单。经济分、现金缺口、车价、存款与收入没有可选透传字段。分享预览、Canvas 和导出文件名也不能包含敏感金额。错误日志只输出预定义错误码，不输出完整输入或存储记录。

刷新后恢复最近草稿；其他标签页更新提示“有另一份更新，是否载入”，未保存草稿不被自动覆盖。删除本机数据需要确认，并恢复到初始视图。

## 5. 测试与验证

| 层次          | 必测内容                                                                |
| ------------- | ----------------------------------------------------------------------- |
| 金额与 schema | 空字符串、0、负数、非有限数、超上限、小数位、首付和残值跨字段约束       |
| 贷款          | 全款、零利率、正利率、极小利率、1 / 84 期、最后一期本金归零             |
| 成本          | PRD 算例、燃油 / 纯电切换、零里程、短于贷款期的持有成本、交通费避免重复 |
| 评分          | 需求权重总和 100、分数界限、赤字封顶、解释因素与输入一致                |
| 状态          | 返回保留答案、草稿恢复、A/B 深拷贝、非法输入不更新有效结果              |
| 平台与 UI     | 存储异常、跨标签提示、键盘和错误焦点、分享字段白名单与静态导出          |

贷款测试同时验证本金累计等于初始本金、余额不为负、利息与期数一致等性质，避免只复制公式写预期。Playwright 覆盖“六题 → 预算 → 结果 → 修改 B → 对比 → 导出”，并加载资源后断网执行核心步骤。

## 6. 实施拆分

1. 应用初始化、主题 token、小车与钱包静态组件。
2. schema、计算引擎、评分解释与单元测试。
3. 完整问答和预算表单、草稿与异常处理。
4. 结果、账单、A/B 比较与实时有效结果更新。
5. 脱敏分享图片、响应式与可访问性验收。

最终交付独立 dist，不添加后端配置、API 密钥或数据库迁移。命令按公共基线提供，实际初始化完成后更新项目 README 的运行方式。
