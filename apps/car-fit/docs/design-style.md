## 3. 买车测评：手绘贴纸风

### 3.1 定位与色板

体验像来到一个轻松的“买车体检站”，由小车和钱包陪用户完成问答，结果是一张有趣但解释清楚的报告。

| 语义            | 建议色值  | 用途                       |
| --------------- | --------- | -------------------------- |
| 页面背景        | `#FFF8EE` | 奶油纸张底色               |
| 卡片表面        | `#FFFFFF` | 题卡和数据区               |
| 主要文字 / 描边 | `#352C28` | 标题、正文、角色轮廓       |
| 次要文字        | `#75665D` | 辅助说明，使用前验证对比度 |
| 主色            | `#BFE7D3` | 主按钮、选中项背景         |
| 强调色          | `#FFC47A` | 进度、徽章、关键道具       |
| 提醒背景        | `#FBE4D8` | 成本压力提示，搭配解释文字 |

卡片建议使用 2px 深棕描边与约 `4px 4px 0` 的硬阴影。少量贴纸可轻微旋转，正文、表单和图表保持端正。

### 3.2 角色与插画

- 原创小车：圆润车身、简洁表情，代表出行愿望；原创钱包：简洁的钱包造型，代表预算意识。
- 两个角色是伙伴，不制造“理性训斥欲望”的关系。
- 首版至少提供：欢迎、思考、记录、解释结果、庆祝五种情绪或姿态，可复用身体和道具。
- 插画使用统一深棕轮廓、平涂色和少量阴影，不采用复杂拟真材质。
- 角色集中出现在开场、题目上方和结果摘要，不在每个输入框旁重复出现。
- 主内容首次可见区域内，装饰插画建议不超过约三分之一；长说明区进一步减少装饰。

### 3.3 页面要求

| 页面       | 必须呈现                                   | 视觉与交互要求                                   |
| ---------- | ------------------------------------------ | ------------------------------------------------ |
| 首页       | 标题、用途、预计耗时、开始按钮             | 小车与钱包主插画；一个清楚的主操作               |
| 需求问答   | 当前题目、选项、题号、上一步               | 一次一道题；整张选项卡可点击；小车沿路线表达进度 |
| 收支与预算 | 有分组的输入、单位、默认值说明、校验反馈   | 可以一屏填写关联字段；滑块必须同步提供数字输入   |
| 结果摘要   | 角色称号、需求分、经济承受力分、一句话解释 | 报告或体检单造型；两个维度分开展示               |
| 成本与对比 | 成本明细、计算假设、两种方案的变化         | 清楚的账单与横向条形图；手机端纵向排列           |
| 分享卡     | 称号、角色、关键结论、作品名称             | 独立竖版排版；默认隐藏收入、存款和负债金额       |

- 问答内容区桌面端建议最大宽度 640px，结果页可扩展至 1040px。
- 可以设置“想买”和“预算”的视觉对话，但不得用夸张总分遮蔽实际成本。
- 用户调整预算时立即更新数值，角色反馈要轻；不能每次拖动滑块都触发庆祝。
- 数据不完整、输入非法和无法生成结果时，必须显示具体原因并保留已填内容。
- 如显示加载过程，应反映实际工作，不添加虚假的长时间“专业分析”动画。

### 3.4 文案示例

| 场景         | 建议表达                                              |
| ------------ | ----------------------------------------------------- |
| 开场         | “带上钱包，给买车计划做个体检。”                      |
| 通勤题       | 小车：“每天通勤多久呀？” 钱包：“我先坐旁边听听。”     |
| 预算压力较大 | “车车很心动，钱包想换个方案。” 下方解释具体成本和结余 |
| 降低预算后   | “换个预算，给生活多留点余地。”                        |
| 结果称号     | “刚需通勤型”“周末出逃型”“从容规划型”                  |

角色称号是趣味表达；结论必须附实际依据。避免“穷鬼”“不配买车”“闭眼买”等评价或过度承诺。

## 与产品方案对应的视觉细化

- 正式名称为“买车前，先算算”，首页副标题说明“测需求、算成本、比方案”。
- 六道需求题使用小车路线进度；预算区从题卡切换为分组表单，保持步骤导航连续。
- 结果首屏分别显示需求分与经济承受力分，不添加模糊综合分。
- 现金缺口或月度赤字是文字与账单提示，不给角色贴负面身份；提示优先于庆祝。
- A/B 对比采用并排账单，手机上下排列，差额需显示正负号与具体含义。
- 原“深棕描边 + 贴纸”仅用于标题、题卡和摘要；长成本表减少装饰，确保数字对齐。
- 分享卡默认不含经济分或财务数字，避免从结果反推出用户预算；与产品脱敏规则一致。
- 增加草稿恢复、非法输入、存储失败、无有效结果、清除确认五类界面状态。
- 交付至少包含：首页、单选题、预算表单、含现金缺口的结果、正常结果、A/B 对比、分享预览的移动与桌面稿。

## H5 与文案精简要求

- 以功能标题和必要说明为主，减少标语、英文装饰、角色旁白与重复引导；保留可爱插画。
- 手机端单列展示核心内容，首屏优先题目或收入；表单在窄屏下重新排布，输入字号至少 16px，按钮触控区域至少 44px。
- 使用 viewport-fit=cover 与安全区留白，不限制用户缩放；弹窗限制在动态视口内，打开时锁定背景滚动，关闭按钮可见。
- 分享提供本机图片预览和下载；浏览器限制下载时提示长按图片保存。全屏不可用时保留页面内专注模式。
- 以现代手机浏览器为目标；触屏模拟覆盖问答、输入、弹窗滚动、隐私与分享，微信等内置浏览器的原生分享能力以宿主支持为准。
