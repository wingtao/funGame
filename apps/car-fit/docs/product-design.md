# 买车前，先算算 · 产品设计文档

版本：v0.1；日期：2026-11-05；状态：首版已实现，运行与验证见 [项目 README](../README.md)。

项目标识：`car-fit`。关联：[设计风格](design-style.md) · [公共设计规范](../../../docs/design-style.md)。本文中的评分、阈值和默认费用是产品建模约定，不代表行业标准或经过验证的金融模型；应在结果解释中公开。

## 架构约束：纯前端

- 必须采用 React + TypeScript + Vite，构建产物为可独立托管的 HTML、CSS、JavaScript 与静态资产。
- 所有业务计算、输入校验、状态管理和分享图片生成均在浏览器执行；不依赖后端、数据库、Serverless / Edge 函数、SSR 或远程计算接口。
- 使用 localStorage 保存本作品设置与状态，不提供账号、云同步或服务端存储。隐私 / 无痕模式、浏览器清理和换设备可能导致数据不可恢复，设置页需说明。
- 分享图片在本机生成与下载，不上传用户输入；原生分享不可用时提供下载入口。资产和必要字体随站点提供，默认使用系统字体，运行时不依赖第三方 CDN 或远程图片。
- 不集成需要保密密钥的 API，不将密钥写入前端包。首版不加入第三方统计、远程日志或数据采集。
- 代码可以被查看和修改，本产品不做防作弊、排行榜或可兑现奖励。
- 首次打开需要从静态托管加载资源；资源加载后核心功能不依赖业务网络请求。首版不承诺离线重新打开，不增加 Service Worker / PWA 离线缓存要求。
- 后续如需 JSON 导入导出，可作为本地备份功能另行设计，首版不扩展范围。

## 1. 产品定位与用户

面向正在考虑第一辆车、希望了解通勤价值与家庭预算影响的用户。通过轻量问答和可调整账单，回答三个问题：我有多需要车、这个方案每月花多少、买车后还剩多少缓冲。

体验目标：约三分钟完成首次测评；不注册、不关联银行；手机端完成全部流程；结果有趣、计算透明，可以比较两个方案。

核心循环：回答问题 → 得到角色结果和账单 → 调整车价 / 首付 → 对比变化 → 保存或分享。

## 2. 首版范围

| 优先级       | 内容                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| P0，首版必做 | 六道需求题、经济输入、燃油 / 纯电成本计算、两维评分、结果解释、A/B 方案比较、本机草稿、数据清除、脱敏分享卡 |
| P1，后续增强 | 插混模型、自定义费用项、场景预设、更多角色皮肤、报告导出                                                    |
| 暂不提供     | 实时车价、车型推荐、保险报价、贷款申请、账号、排行榜、自动节假日或地区成本数据                              |

首版为人民币、私家车、固定月收入与等额本息模型。购车费用和养车费用均由用户填写；示例只帮助理解，修改前明确标记“示例估算”。

## 3. 信息架构与流程

1. 首页：说明用途、耗时与本机保存方式；“开始体检”，有有效草稿时提供“继续上次”。
2. 用车需求：一次一题，显示题号，选中后点击下一步；可返回，保留答案。
3. 家庭预算：收入、支出、现有负债与可用存款；提示按实际承担购车成本的同一家庭口径填写。
4. 购车和使用方案：购车、贷款、行驶里程、能源、停车、保险与保养。
5. 结果：结论摘要 → 两维分数 → 月度现金流 → 持有总成本 → A/B 对比 → 分享 / 修改 / 清除。

直接进入结果但缺少有效输入时，跳到首个未完成步骤并说明原因。刷新恢复草稿；重置需确认，取消后不丢数据。

## 4. 需求问答与评分

每题按 0 / 1 / 2 / 3 分记录，所有题必答。表中选项按得分从低到高排列。

| 题目                         | 选项                                                 | 权重 |
| ---------------------------- | ---------------------------------------------------- | ---- |
| 当前单程通勤时间             | ≤15 分钟 / 16–30 / 31–60 / >60 分钟                  | 20   |
| 现有公共交通是否方便         | 直达且稳定 / 一般方便 / 换乘多或班次少 / 几乎不可用  | 20   |
| 家庭接送或照护频率           | 无 / 每月几次 / 每周几次 / 几乎每天                  | 20   |
| 自驾出游或跨区需求           | 几乎没有 / 每月不到一次 / 每月 1–3 次 / 每周至少一次 | 15   |
| 因现有交通造成的不便         | 几乎没有 / 偶尔 / 每周多次 / 几乎每天                | 15   |
| 对运物、夜间或临时出行的需求 | 几乎没有 / 每月几次 / 每周几次 / 几乎每天            | 10   |

`需求分 = round(Σ(题目得分 ÷ 3 × 权重))`，范围 0–100。0–39 为低，40–69 为中，70–100 为高。结果展示贡献最高的两项因素，说明“需求强度不等于买车能节省多少时间”。

不强制输出综合买车分：需求与经济条件必须分别显示，避免一个总分掩盖风险。

## 5. 输入与校验

| 字段组   | 字段                                             | 约束 / 说明                                                            |
| -------- | ------------------------------------------------ | ---------------------------------------------------------------------- |
| 家庭预算 | 月到手收入、必要生活支出、其他贷款月供、可用存款 | 均 ≥0；月收入必须 >0；生活支出不含现有交通费和贷款，避免重复           |
| 现有交通 | 买车前月交通费、买车后仍保留的月交通费           | 均 ≥0；后者可为 0，不能默认认为现有支出全部消失                        |
| 购车     | 车辆成交价、额外一次性费用、首付                 | 车价 >0；额外费用单列，避免与报价内已含费用重复；0≤首付≤车价           |
| 贷款     | 贷款月数、年利率                                 | 仅贷款本金 >0 时必填；月数 1–84 整数，年利率 0–30%；只接受等额本息口径 |
| 用车     | 燃油 / 纯电、月里程、百公里能耗、能源单价        | 均 ≥0，选择的能源字段必须填写；0 表示明确的零值                        |
| 固定费用 | 月停车、年保险、年保养、年其他固定费用           | 均 ≥0；明确不含能源费用                                                |
| 长期估计 | 持有年数、期末残值、缓冲月数                     | 持有年数 1–15 整数；0≤残值≤车价；缓冲默认 6 个月，可设 1–24            |

金额以元输入，最多两位小数；利率最多两位小数。金额 / 月里程等非比例输入首版上限为 100,000,000，超限给出就近错误。空值不视为 0，拒绝负数、非有限数、非法文本。提交时聚焦首个错误字段，不清空其他内容。

## 6. 成本计算口径

所有内部金额以分存储，利率和计算中间值保留精度，展示时四舍五入到分。年费用折月的计算不提前取整，避免累计误差。

定义：车价 V、额外购车费用 F、首付 D、贷款本金 P=V−D、贷款期数 n、月利率 r=年利率÷12。

- 无贷款时月供 M=0。
- 有贷款且 r=0 时，M=P÷n。
- r>0 时，M=P×r×(1+r)^n÷((1+r)^n−1)。全期利息 I=M×n−P。
- 月能源费用 E=月里程÷100×百公里能耗×能源单价。
- 月养车费 O=E+月停车+(年保险+年保养+年其他固定费用)÷12。
- 一次性支出 U=D+F；购车后存款 S=可用存款−U。
- 买车前月结余 B=收入−生活支出−其他贷款月供−现有月交通费。
- 贷款期间月结余 A=收入−生活支出−其他贷款月供−M−O−买车后保留交通费。
- 相比原交通的月增支 Δ=M+O+买车后保留交通费−现有月交通费，可为负。
- 还清贷款后的月结余使用 M=0 另行展示。

月支出展示是当前方案在贷款存续期间的估算，不把“全期利息”再次加进月供。

持有总成本：`V+F+J+O×12×持有年数−期末残值`。J 为持有期内累计利息：先按每期“剩余本金×月利率”计算利息与本金偿还，累计前 min(持有月数,n) 期。持有期内提前卖车时另列剩余本金，并假设按剩余本金结清、无提前还款费用。不要把月供本金或折旧再次加到上述公式。期末残值为用户假设，非预测报价。

计算核对例：车价 100,000、首付 40,000、零利率 60 期、额外费用 5,000，月养车 800。月供应为 1,000，一次性支出 45,000，车辆月现金支出为 1,800。无贷款时利息和月供均应为 0。

## 7. 经济承受力评分与结论

采用透明的两项预算指标，不用行业标准的名义包装。设 `clamp(x)=min(1,max(0,x))`。

- 现金流项 C=clamp(A÷收入÷0.30)。月结余达到收入 30% 时该项满分。
- 现金储备目标 T=缓冲月数×(生活支出+其他贷款月供+M+O+买车后保留交通费)。
- 储备项 R=clamp(S÷T)；T=0 时，S≥0 取 1，否则取 0。
- 经济承受力分=round(100×(0.6×C+0.4×R))。
- 若 S<0 或 A<0，分数最高为 39，并在最前解释现金缺口或月度赤字；不能被其他高分抵消。
- 0–39：“先调整方案”；40–69：“有压力，留点余地”；70–100：“当前假设下较从容”。

角色称号优先反映需求：高需求“刚需通勤型”，中需求且出游题≥2“周末出逃型”，其余“从容规划型”。经济结论独立展示，不以羞辱性称号表现资金不足。至少列出两条具体依据，所有建议可追溯至输入与计算。

## 8. 对比、分享与数据

- 进入对比时复制当前完整输入为 B，A 为基准快照；两份预算互不影响，需求问答相同。
- 对比至少展示一次性支出、月供、养车费、月结余、剩余存款、持有总成本和经济承受力分；显示每份方案的关键假设。
- 分享以图片为主，导出前预览；默认仅含角色、需求分和通用结论，不含经济分、成本、收入、存款或负债值。首版不提供财务数字开关。
- localStorage 使用 `fungame:car-fit:v1`，保存带版本号的答案、预算与两个方案；不把财务数据写入 URL 或日志。
- 解析存储时按未知数据校验。数据损坏或版本不支持时提示重填，不让页面崩溃；存储不可用时允许当前会话继续并明确“未保存”。
- 首版不加入第三方行为分析。清除数据只清理本作品的键，不影响其他作品。

## 9. 首版验收

- 静态构建可独立部署，无后端启动步骤；页面资源加载后，禁用网络仍可完成核心计算、修改设置和本机图片导出。
- 网络请求与日志检查中不包含用户输入；本地资产正常加载，分享不依赖远程截图服务。

- 六题完成、返回修改、刷新恢复、预算校验和 A/B 比较可完整运行。
- 零利率、全款、零里程、零收入非法输入、首付超过车价、存款不足、月结余为负均有明确表现。
- 短于贷款期的持有总成本只累计对应期间利息，并展示剩余本金。
- 算例结果正确；同一输入刷新与重算结果一致；评分边界 39/40、69/70 可验证。
- 分享图与导出内容不泄露敏感数据；本机存储失败与损坏有降级路径。
- 完成对应设计规范中的键盘、移动端、对比度与减少动画验收。

## 10. 实施与效果验证

模块设计、依赖与测试落地方式见 [技术方案](technical-design.md)，公共约束见 [纯前端技术基线](../../../docs/frontend-architecture.md)。

使用 React + Vite + TypeScript；计算函数与界面分离，评分规则带版本。Vitest 验证公式与边界，Playwright 覆盖完成测评、修改和对比流程。

首版通过小范围试用观察用户能否独立完成、能否解释两个分数、能否找到月结余并比较方案。后续如需记录完成率或分享率，另行定义不含财务输入的统计方案，首版不预埋采集。
