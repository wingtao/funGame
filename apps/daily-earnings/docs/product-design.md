# 今日已赚 · 产品设计文档

版本：v0.1；日期：2026-11-05；状态：首版已实现，运行与验证见 [项目 README](../README.md)。

项目标识：`daily-earnings`。关联：[设计风格](design-style.md) · [公共设计规范](../../../docs/design-style.md)。

## 架构约束：纯前端

- 必须采用 React + TypeScript + Vite，构建产物为可独立托管的 HTML、CSS、JavaScript 与静态资产。
- 所有业务计算、输入校验、状态管理和分享图片生成均在浏览器执行；不依赖后端、数据库、Serverless / Edge 函数、SSR 或远程计算接口。
- 使用 localStorage 保存本作品设置与状态，不提供账号、云同步或服务端存储。隐私 / 无痕模式、浏览器清理和换设备可能导致数据不可恢复，设置页需说明。
- 分享图片在本机生成与下载，不上传用户输入；原生分享不可用时提供下载入口。资产和必要字体随站点提供，默认使用系统字体，运行时不依赖第三方 CDN 或远程图片。
- 不集成需要保密密钥的 API，不将密钥写入前端包。首版不加入第三方统计、远程日志或数据采集。
- 代码可以被查看和修改，本产品不做防作弊、排行榜或可兑现奖励。
- 首次打开需要从静态托管加载资源；资源加载后核心功能不依赖业务网络请求。首版不承诺离线重新打开，不增加 Service Worker / PWA 离线缓存要求。
- 后续如需 JSON 导入导出，可作为本地备份功能另行设计，首版不扩展范围。

- 时间来自设备时钟，不请求网络校时服务。页面关闭后不继续执行代码，也不发送后台通知；重新打开按当时的设备时间重算，休眠和后台恢复同理。
- 时区计算工具随应用打包，使用浏览器时区能力或本地随包数据，不通过远程接口查询工作日、节假日或时区。

## 1. 产品定位与用户

面向希望获得轻松工作反馈的上班族，将工资换算为随计薪时间增长的估算收入，配合原创小动物工位场景与生活目标。

核心体验：设置一次 → 每天打开 → 看金额和工作进度 → 达成咖啡 / 午饭目标 → 下班结算。产品显示估算，不连接雇主或实际支付系统。

目标：首次设置约一分钟；再次打开直接进入今日画面；长时间放在旁边不会持续打扰。

## 2. 首版范围

| 优先级       | 内容                                                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| P0，首版必做 | 月薪 / 时薪、固定周工作日、当月逐日覆盖、固定日班与午休、实时收入、状态和倒计时、生活目标、隐私模式、全屏、本机保存与清除 |
| P1，后续增强 | 历史日报、换肤、更多场景、跨夜班、多段班次、新标签页或侧边栏插件                                                          |
| 暂不提供     | 工资排名、自动税费计算、自动节假日调休、账号、云同步、实际提现与财务账户连接                                              |

首版仅人民币，单工作时区和固定日班。没有历史记录功能；刷新恢复的是当前设置与当天目标状态，不意味着保存了完整薪资历史。

## 3. 页面与用户流程

1. 首次进入：展示短说明，可选“体验演示”或“设置我的工资”。演示有常驻标识，使用虚拟数据，不覆盖正式设置、不生成个人成就。
2. 设置薪资：选择月薪 / 时薪、输入金额，推荐到手口径；若选税前，收入区明确标“税前估算”。
3. 设置安排：工作时区、周工作日、上下班、午休与午休是否计薪；当月日历可标工作 / 休息，以处理调休或请假。
4. 可选设置目标：提供咖啡、午饭等示例，用户编辑金额或跳过。
5. 今日主界面：收入、计薪状态、工作进度、下班倒计时、小动物场景、当前目标及工具入口。
6. 设置修改：展示“修改后将按新规则重算今日”的说明，保存才生效；取消保留旧设置。
7. 下班后：主界面原位变为今日结算，保留设置、隐私和目标入口，不强制弹窗。

无有效配置时不展示伪造的个人收入。设置是对话框或独立视图均可，必须支持返回与键盘操作。

## 4. 数据与输入规则

| 字段         | 规则                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| 计薪模式     | 月薪或时薪，切换保留各自草稿，保存时仅所选模式生效                         |
| 薪资金额     | >0，最多两位小数，上限 100,000,000 元；月薪 / 小时单位随模式切换           |
| 薪资口径     | 到手或税前，只影响说明；不做税费换算                                       |
| 工作时区     | 首次取浏览器 IANA 时区，允许更改；页面展示当前工作时区                     |
| 周工作日     | 周一至周日多选，至少一天                                                   |
| 上下班       | 分钟精度，00:00≤上班<下班≤23:59；首版不接受跨夜班                          |
| 午休         | 可关闭；开启时须位于上下班内，起点<终点；非计薪午休不得覆盖整个班次        |
| 当月日历覆盖 | 对单日设置为工作或休息；月份切换可查看和提前编辑，不自动导入节假日         |
| 计薪工作日数 | 默认按当月工作日历计算，允许手动正整数覆盖 1–31；显示其与日历天数是否不同  |
| 趣味目标     | 0–5 个，名称 1–20 个字符，金额 >0 且≤100,000,000，最多两位小数，按金额排序 |

工作安排输入保持统一口径。手动计薪日数只改变月薪换算的分母，不改变日历里哪些日子上班；UI 必须明确这一点。首版目标是“今日累计收入达到该金额”，多个目标不是依次扣款，不暗示实际存款。

## 5. 时间、金额与进度规则

### 5.1 当日计薪时段

一切日期与时刻按设置的工作时区解释，设备显示时区改变不自动修改工作安排。

- 当天是否工作先查日历覆盖，否则查周工作日。
- 日班定义半开区间 `[上班,下班)`；午休为 `[午休开始,午休结束)`。
- 午休计薪时，整个班次为计薪时段；不计薪时，从班次扣除午休区间。
- 计薪时间使用时区日期时间对应的实际时间戳求交集，秒为单位；不把已播放的计时器次数当作工作时长。
- 对夏令时造成的不存在或有歧义的上下班时刻，首版阻止该日期计薪并提示调整时刻，不能静默选择一个时间。正常日期照常使用。

### 5.2 收入计算

设当天完整计薪秒数为 H，当日截至当前已过去的计薪秒数为 E，满足 0≤E≤H。

- 月薪模式：日估算收入 D=月薪÷本月计薪工作日数 N；今日收入=D×E÷H。
- 时薪模式：今日收入=时薪×E÷3600。
- 休息日收入为 0；上班前为 0；下班后固定为当天完整计薪金额。
- N 默认来自当月工作日历，覆盖值只作用于对应月份。N=0 时不进行除法，显示“本月未安排工作日”；月薪用户需调整日历或分母后才能生成该月日收入。
- 内部薪资与目标以分保存；计算过程中保留精度，仅显示时四舍五入。目标判断使用未四舍五入的累计收入，避免提前达成。

核对例：月薪 10,000，N=20，上班 09:00、下班 18:00，12:00–13:00 午休不计薪，普通无夏令时日期 H=8 小时。12:00 / 13:00 均为 187.50 元，18:00 为 500 元。时薪 50 元时上述时刻分别为 150 / 150 / 400 元。

### 5.3 进度、刷新与时钟变化

- 工作进度=已经过去的班次实际秒数÷完整班次实际秒数，含午休；标签为“工作日进度”，不是收入进度。
- 下班倒计时按当前时刻与下班时刻计算，最低为 0；上班前改为开工倒计时，休息日不展示当日下班倒计时。
- 下一工作日按已有日历覆盖与周安排查找；若未来 366 天内无有效班次，显示“请检查工作安排”，不无限查找。
- 显示建议每秒更新一次；后台暂停装饰动画。刷新、休眠恢复、切回前台时，按当前时间重算。
- 工作日期跨过午夜后清空当日展示与成就状态，重新选择当天状态；上月手动分母不沿用到新月份。
- 本机时钟修改后按新的当前时间重算，金额可能回退，说明其依赖设备时间；不通过只增不减的假数字掩盖变化。
- 保存薪资、安排、日历或分母后按新设置重算今日，不视为真实补发工资，不保留旧金额叠加。

## 6. 工作状态机

状态按“配置无效 → 日历休息 → 上班前 → 下班后 → 午休 → 工作中”的顺序判断。

| 状态              | 金额           | 场景             | 核心说明             |
| ----------------- | -------------- | ---------------- | -------------------- |
| 未设置 / 配置错误 | 不显示个人估算 | 欢迎或整理工位   | 引导完成设置         |
| 休息日            | 0              | 看书、晒太阳     | 提示下一工作日       |
| 上班前            | 0              | 放包、准备水杯   | 开工倒计时           |
| 工作中            | 随计薪时间增长 | 敲键盘、伸懒腰   | 今日收入和下班倒计时 |
| 午休计薪          | 继续增长       | 吃饭或靠椅休息   | 明确“午休计薪”       |
| 午休不计薪        | 暂停增长       | 吃饭或靠椅休息   | 明确“午休暂停计薪”   |
| 下班后            | 当日完整值     | 合上电脑、拿起包 | 今日结算             |

首版没有人为暂停计薪按钮，避免与已声明的班次计算冲突；只暂停动画不影响收入计算。加班也不自动计入，应修改工作安排并接受今日重算。

## 7. 趣味目标与反馈

- 目标使用稳定 ID，保存名称、金额与顺序；当前目标为尚未完成的最小金额目标，其余可展开。
- 页面已运行且收入自然跨过目标时，播放一次轻庆祝；多目标同一轮达成合并为一条反馈。
- 首次打开、刷新、后台恢复、修改配置或新增 / 修改目标时，已满足目标直接标完成，不补播庆祝。
- 当天已经庆祝的目标记录于本机，刷新不重复。金额回退后完成状态按当前金额更新，但当天同一目标不再庆祝。
- 目标不扣减收入，说明“相当于赚到这笔钱”；所有目标完成后展示安静的完成状态，不强制添加更大目标。
- 动画最多约一秒，不抢焦点、不挡金额、不默认发声；减少动画模式改用静态状态提示。

## 8. 隐私、本机数据与异常

- localStorage 使用 `fungame:daily-earnings:v1`，保存版本、配置、各月日历覆盖、目标、隐私偏好和当天庆祝 ID；不保存完整收入流水。
- 隐私模式持久化。打开页面时先读取隐私偏好再展示数字，避免先闪现真实金额；薪资、今日金额、目标金额及相关工具提示都需遮蔽。
- 处于隐私模式时打开设置，先确认“编辑将显示薪资”，确认仅本次显示表单，不自动关闭主页隐私模式。
- 分享卡先预览；默认只分享场景、通用文案和工作进度，勾选后才能加入今日金额；永不加入月薪或时薪。
- 财务设置不写入 URL、日志、错误上报或第三方统计。首版不加入远程分析，不申请通知权限。
- 本机存储不可用时仍可使用，但明确提示刷新会丢失设置；数据损坏需提示恢复设置，页面不崩溃。
- 重置需确认，只清除本作品数据。多标签页通过 storage 事件同步配置，收到变更后重算且不补播庆祝。
- 全屏不可用时降级为页面内专注模式，不影响退出、设置和隐私入口。

## 9. 首版验收

- 静态构建可独立部署，无后端启动步骤；页面资源加载后，禁用网络仍可完成核心计算、修改设置和本机图片导出。
- 网络请求与日志检查中不包含用户输入；本地资产正常加载，分享不依赖远程截图服务。

- 首次设置、跳过目标、演示与正式模式、再次打开恢复均可运行。
- 计薪 / 不计薪午休、开工和下班边界、周末、日历覆盖、跨月、零工作日均符合规则。
- 两种薪资模式通过给定算例；输入错误不导致 NaN、Infinity 或负收入。
- 切后台、休眠恢复、刷新、修改设置和设备时区变化后，估算依据一致。
- 夏令时异常时刻有明确反馈；首版拒绝跨夜班。
- 目标自然达成、重新打开、多目标同时达成、金额回退和配置重算不重复庆祝。
- 隐私模式无金额闪现，分享默认脱敏，设置敏感值需主动展示。
- 本机存储失败、损坏、多标签页与全屏失败都有可用路径。
- 完成对应风格规范中的可访问性、移动端与低动效验收。

## 10. 实施与效果验证

模块设计、依赖与测试落地方式见 [技术方案](technical-design.md)，公共约束见 [纯前端技术基线](../../../docs/frontend-architecture.md)。

使用 React + Vite + TypeScript，场景采用轻量图片 / SVG 与 CSS 动画。时间计算使用支持 IANA 时区的成熟工具；渲染、计算与持久化分开，使用可注入的当前时间进行测试。

Vitest 覆盖计薪区间、跨月、目标与时区边界；Playwright 覆盖首次设置、恢复、隐私与修改流程。试用时观察是否能一分钟内完成设置、能否理解午休计薪和估算口径、长期挂着是否打扰。首版不为留存率采集个人薪资数据。
