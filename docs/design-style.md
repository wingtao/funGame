# FunGame 设计风格规范

本文将 UI 调研结论转化为首版设计与实现要求，适用于 `car-fit`（买车测评）与 `daily-earnings`（今日已赚）。后续作品可参考通用规范，但应根据自己的体验确定风格。

“必须”表示验收要求；“建议”表示默认方案；示例文案可以调整。本文中的配色、尺寸、角色和动效参数是本项目的设计提案，不是参考产品的设计数据。首版已使用原创 SVG 角色与场景实现；后续迭代继续按本文与项目风格要求验证。

## 1. 总体定位

**可爱的角色、成年人的幽默、清楚的信息。**

- 用原创角色、圆润造型、生活化道具和少量动作建立可爱感。
- 用通勤、咖啡、午饭、开会、下班等共同经历产生幽默，保持温和、有分寸。
- 题目、金额、结果和操作必须优先于插画，用户无需理解角色设定即可使用。
- 两个作品共享亲切的语气、清晰的字体和控件反馈；分别采用手绘贴纸风、温暖二维插画风。
- 组件库提供交互基础，最终视觉必须按本文定制，避免直接保留模板的默认后台界面。

### 不采用的方向

- 大面积霓虹渐变、玻璃面板、强烈发光和密集金融行情屏。
- 通过满屏 Emoji、随机贴纸或大量弹窗制造热闹。
- 同一页面混用写实照片、像素角色、三维黏土与手绘插画。
- 用收入高低、负债或消费选择羞辱用户；用悲惨表情惩罚用户。
- 通过持续抖动、红点、强提醒或默认音效争夺注意力。

## 2. 通用视觉基础

### 2.1 字体与信息层级

| 元素                | 桌面端建议 | 移动端建议 | 要求                       |
| ------------------- | ---------- | ---------- | -------------------------- |
| 页面主标题          | 32–40px    | 28–32px    | 字重 700，最多两行         |
| 区块标题 / 当前题目 | 22–28px    | 20–24px    | 字重 600–700               |
| 正文 / 选项         | 16–18px    | 16px       | 行高 1.5–1.7               |
| 辅助说明            | 14px       | 14px       | 仍须满足文字对比度         |
| 今日收入主数字      | 64–88px    | 44–60px    | 随可用宽度适配，不截断金额 |

- 默认中文字体栈为 `"PingFang SC", "Microsoft YaHei", system-ui, sans-serif`，无需下载字体也能使用。
- 金额和倒计时必须使用等宽数字 `font-variant-numeric: tabular-nums`，减少跳动。
- 手写或像素字体只可用于短标签、装饰，不用于题目、正文和金额。
- 金额始终带币种或单位；“估算”“每月”“今日”等口径应与数字就近展示。

### 2.2 间距、形状与控件

- 使用 4px 基础间距，常用 8 / 12 / 16 / 24 / 32 / 48px。
- 卡片内边距：移动端至少 16px，桌面端建议 24px。
- 卡片圆角 20–24px；按钮和输入框圆角 12–16px。
- 主按钮高度至少 48px，其他交互目标至少 44 × 44px。
- 默认、悬停、按下、选中、焦点、禁用、错误状态必须完整；移动端不能依赖悬停提示。
- 按钮按下可下移 1–2px，阴影同步缩短；不得让周围布局移动。
- 必须提供清楚的键盘焦点，不能只靠颜色区分选中或错误状态。
- Lucide 等线性图标统一为约 2px 描边；插画道具与功能图标保持职责区分。

### 2.3 颜色与可访问性

以下两套色板各自使用，必须映射为 `background`、`surface`、`text`、`muted`、`primary`、`border`、`success`、`warning` 等语义变量。

- 正文对比度至少 4.5:1，大字和必要的控件边界至少 3:1；这些是验收目标，不能假设色板任意组合都满足。
- 浅薄荷、浅橙等用于背景时搭配深色文字；不默认使用白色文字。
- 分数和状态必须同时提供文字、图形或图标说明，不能只用红绿表达。
- 首版交付完整浅色主题；夜间场景不等于深色主题，场景变化后控件仍须清晰。

## 5. 动效与声音

| 动效            | 建议参数   | 使用要求                                   |
| --------------- | ---------- | ------------------------------------------ |
| 按钮 / 选项反馈 | 120–180ms  | 状态明确、幅度小                           |
| 题目切换        | 180–240ms  | 透明度或 8–12px 位移，切换后焦点合理       |
| 结果首次出现    | 240–400ms  | 内容尽快可读，不能等待动画才能操作         |
| 角色日常动作    | 2–4 秒一轮 | 动作之间留停顿，避免所有道具同时运动       |
| 目标达成        | 600–1000ms | 单次轻庆祝，不遮挡主数字；仅跨过目标时触发 |

- 今日已赚同一目标当日不重复庆祝，不因刷新或切回页面再次弹出；多个目标同时达成时合并反馈。
- 持续动画允许暂停，遵循 `prefers-reduced-motion`：关闭循环、位移和纸屑，保留静态状态与必要数值更新。
- 页面不可见时暂停装饰动画，恢复后按真实时间重新计算金额。
- 默认静音。未来加入音效时必须提供主动开启和关闭入口。
- 装饰动画不抢焦点；不要让屏幕阅读器每秒播报金额，里程碑可做温和状态通知。

## 6. 响应式、资产与实现约定

- 首批两个作品必须为纯前端静态网站。设计不得引入注册、云同步、服务端报告、上传截图生成或必须联网的角色素材。
- 分享卡在浏览器生成，预览、脱敏与下载均可在本机完成；原生分享不可用时提供下载。
- 字体优先使用系统字体，插画与其他必要资产随站点提供。设置页说明数据仅保存在当前浏览器，不使用“已同步到云端”等不真实状态。

- 至少检查 360px、390px、768px 和 1440px 宽度；320px 下也不得丢失核心功能或出现页面级横向滚动。
- 文字放大至 200% 时核心流程仍能完成；长金额、长目标名和错误提示不能溢出或盖住按钮。
- 首版所有功能支持键盘操作；表单有真实标签，错误与字段关联，页面切换后焦点有明确去向。
- 功能图标按钮提供可访问名称；纯装饰插画标记为装饰，有信息的角色状态另提供文字说明。
- 插画建议使用 SVG 或经过压缩的 WebP / AVIF；预留宽高，避免图片加载后布局跳动。静态资源设定尺寸预算，不直接使用大视频作背景。
- 原创角色需保留可编辑源文件和状态清单；外部资产记录作者、来源和许可。参考产品的角色、截图和品牌标志不能直接变成发布素材。
- 每个项目在自身目录维护主题变量和资产，不在首版为了形式统一而强行建立公共 UI 包。
- 每个首版角色至少形成统一比例、轮廓、色板和表情的资产说明，防止不同状态看起来像不同角色。

## 7. 设计交付与验收

实现前，每个作品至少准备首页 / 主界面、关键操作过程、结果 / 状态页的移动与桌面设计，并列出使用的角色状态。设计稿可采用可运行页面，但需要覆盖以下验收项。

### 通用验收

- [ ] 配色映射为语义变量，文字、控件和焦点对比度验证通过。
- [ ] 字体、圆角、间距、图标与插画语言统一。
- [ ] 页面有明确主操作，金额或当前题目优先可见。
- [ ] 控件状态、键盘操作、标签和错误提示完整。
- [ ] 在目标宽度、200% 文字放大、长内容下可正常使用。
- [ ] 减少动画偏好生效；默认静音，无频繁打扰。
- [ ] 幽默温和，文案与数据和状态一致。
- [ ] 资产原创或具备使用许可，未直接复制参考产品素材。

### 买车测评验收

- [ ] 小车与钱包的角色风格一致，插画不妨碍问答和输入。
- [ ] 问答进度清楚，支持返回并保留答案。
- [ ] 需求、经济承受力、成本与假设能分别查看。
- [ ] 调整预算后更新结果，反馈不遮挡操作。
- [ ] 分享卡默认不含收入、存款和负债具体金额。

### 今日已赚验收

- [ ] 五种工作状态均有清楚的文字和相应场景。
- [ ] 金额更新不造成明显跳动，超长金额可完整读取。
- [ ] 工作、午休、下班和休息日的计薪表现与设置一致。
- [ ] 目标达成反馈不重复，隐藏金额完整覆盖敏感展示。
- [ ] 全屏、移动端和低动效模式下仍可查看状态与设置。
